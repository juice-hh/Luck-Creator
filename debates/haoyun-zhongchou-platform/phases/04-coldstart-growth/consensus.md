# 阶段 4 共识 · 冷启动与增长

> 2 轮辩论。第 2 轮 Proposer 对全部必须回应均以诚实让步回应，得出"无强增长引擎"的关键结论。硬性检查通过。

## 已达成共识

1. **冷启动：两级启动**。<15 条授权档案=只做静态原型不上线；15-20 条=封闭内测、明确标注"试运行档案池"、不伪装成熟；40 条以上=公开试运行。授权档案来源优先级：① 熟人一对一 ② 自己公开招募表单 ③ 已公开内容二次授权 ④ 垂直群自愿；**陌生私信仅作补充**（3-5% 转化下要 40 条需上千私信，个人项目不可承受，且有封号风险）。空池用异步窗口池混入档案、诚实不伪造（"这里还很小"）。

2. **档案库续充不靠冷回流，靠"结束节点"峰值即时贡献**："我过了 / 先放下"按钮 = 核心贡献入口，留言是结束仪式的一部分（直接留一句 / 填空式 / 从手账选），显式授权匿名。现实更新速率约**每月个位数条**（低，但个人项目可用；想快速扩张则不够）。

3. **诚实结论：这个产品没有真正的强增长引擎**。好运卡是弱传播 / 内容贡献机制，不是病毒传播链（低谷接收者 B 不会立刻变给予者，B 留言进公共池≠C 收到 B 的卡，链在 B 处断）。现实增长 = 作者手动拉种子 + 节点后留存 + 少量好运卡自然回访 + 缓慢口碑。**现实天花板**：6 个月内几百到一两千访问、几十到几百条档案，小圈层，是"低维护情绪器物"而非自增长社区。

4. **留存（健康钩子）**：福气回声（只显"被收下/被读到"的抵达感，不显阅读量/赞/排名/连续天数）+ 节点手账（**时间轴/事件触发**，如"待了 14 天存个小结"、点"我过了"、节点结束 7 天后轻召回，**不依赖高频访问**）+ 三类健康召回（回声召回 / 用户自设约定召回 / 季节节点召回一年 4-6 次），**绝不做 daily push / streak / "X天没来" / "好运快过期"**。

5. **最小可运营状态（MVO）= 每周 2 小时**：固定 3 节点、自动轮换档案、只审核新增内容、不维护社群、不每日运营、不做人工活动。最小状态下产品不会立刻死，但会停止增长（"安静的小工具"而非"增长机器"）。

6. **止损判据**：连续 6 周每周自然新增档案<2 条 / "我过了"后留言转化<10% / 好运卡打开<20% 且 24h 回访<5% / 新用户三段式完成<30% / 作者每周 2 小时仍负担明显 / 反馈集中"像签语/树洞/没差异"——出现 ≥3 条即承认 fallback 是终点，停止平台化投入，保留为个人作品或关停。

7. **一致性补丁**：实名采集→匿名展示的信任裂缝须在授权页显式说明（采集可实名沟通、展示永久匿名、可随时撤回、入库前模糊化人称/时间/地点）；"送给一个需要的人"默认低压版（"送给未来某个需要的人"），不要求识别具体朋友。

## ⚠️ 交棒 Phase 5 的核心判断
- **T5（决定性）判断标准之争**：以"商业化平台"衡量，当前方案**大概率不值得做**；以"个人可长期维护的小作品 / 低成本公益工具"衡量，**可以做一个小验证**。Phase 5 必须先定标准，再下"该不该做"的结论。
