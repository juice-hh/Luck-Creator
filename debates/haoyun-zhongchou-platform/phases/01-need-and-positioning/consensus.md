# 阶段 1 共识 · 需求与定位

> 2 轮辩论（Proposer GPT-5.4 / Reviewer Claude 双视角）。第 1 轮 6 条"必须回应"已在第 2 轮全部解决；第 2 轮新增 4 条高风险张力，带入后续阶段。

## 已达成共识

1. **需求真实，但非强刚需**。它是"人在不确定事件前需要一个低成本、低羞耻、可重复的心理安放动作"——情绪止痛片，不是刚需工具。是**事件驱动、焦虑高峰才打开**的低频情绪产品，**不能按日活工具设计**。

2. **定位需要重写**：从"好运众筹平台"改为**"匿名低压表达 + 轻量真实回应 + 自我仪式兜底"的情绪产品**（"好运池 / 心愿池"，而非"众筹平台"）。"众筹平台"叙事会让人误以为有严肃互助价值，进入后落差大。

3. **不可替代点 = 半匿名祝福"场域"**：无需金钱、无需熟人暴露、无需强转发的低压力小仪式场。这补的是微信/微博/小红书做不了的"我需要一点回应，但不想向任何具体的人求助"。**场域感做不出来，产品就不值得做。** 差异化不在游戏化货币、也不在广场本身。

4. **0 回应必须用自我仪式兜底**：心愿发出先敲木鱼自我安放；广场不显示"0 祝福"计数；24h 无人回应给"归档式安慰"；**绝不用系统账号/机器人冒充真人祝福**（会污染信任与验证）。第一次心愿的成功反馈必须由用户自己完成，不依赖他人。

5. **冷启动只能靠真人小种子池 + 主题池**：100–300 真实种子用户、限定一个主题池（考前/求职/病中陪伴/深夜安心）、限定 3–7 天窗口、不用机器人。MVP 只验证 3 件事：①愿否放下半匿名心愿 ②愿否给陌生人送好运 ③少量真实回应下愿否回访。不能验证网络效应/长期留存/开放广场繁荣/商业化。

## ⚠️ 重大张力（与现有方案 spec 冲突，需用户决策）

- **T1 · 双货币去留**：辩论倾向**砍掉双货币（好运值/积福值）**，改为单一"好运"+ 行为记录（积福降为事后称号）。**但这与已定稿 spec 的"双货币骨架"直接冲突**——spec 里双货币正是用来锁死"广场由给予侧驱动"的核心机制。**这是必须由用户拍板的方向性选择**，Phase 2 将专门辩论其后果。
- **T2 · 定位改名**：从"好运众筹"改为"好运池/心愿池"，与产品原名冲突，需用户确认是否接受重定位。

## 开放张力（带入后续阶段）
- **UX-A 给予动机真空**（砍双货币后，焦虑中的用户凭什么主动给陌生人送好运？即时反馈是什么）→ Phase 2 核心议题。
- **UX-C 社交是"主菜"还是"彩蛋"**：自我仪式兜底若能独立闭环，广场可能沦为可有可无 → 产品退化成"体面版电子木鱼"。必须二选一，否则产品形态与冷启动目标互相打架 → Phase 2/3。
- **业务-A 种子用户招募路径**（个人项目无预算，100–300 真实场景用户从哪来）→ Phase 4。
- **业务-C 主题池运营是隐藏的持续负担**（主题谁定、何时切换、22:00 假设是否成立）→ Phase 4。
- **业务-D "焦虑时会不会想起打开"是习惯养成问题**，非差异化能解决 → Phase 4。
- **业务-存 半匿名内容的合规边界**（ICP 备案、实名可追溯）→ 上线前硬约束，存档。
