## Response to Reviewer（逐条回应）

### U1【接受】
“不做排行榜”不够。修订为：积福值不再是用户可管理的余额，而是“给予痕迹”。

具体机制：

1. 不显示总额、不显示进度条、不显示“还差多少”。
2. 不存在兑换、解锁门槛、连续任务、等级、稀缺卡池。
3. 每次仪式结束只出现一句轻反馈，例如“你刚刚也给 2 个同样在等结果的人留了好运”。
4. 福气卡不是“用积福值换”，而是本次仪式的收束物；送好运只会改变卡片文案或回声内容，不改变获得资格。
5. 积福值仅作为后台风控与节奏控制信号，例如限制刷屏、控制每次可送数量，不作为用户目标。

所以我接受 Reviewer 的批评：如果存在“积福值 → 福气卡”的可见兑换链，它一定会滑向资源化。修订后切断这条链。

### U2【承认为权衡】
“仪式后更愿给予”不是必然。仪式确实可能形成心理闭环，用户最自然的动作是离开。

因此产品不能把“仪式后送好运”设计成强转场，而要设计成低摩擦的余波动作：

- 仪式完成后，默认先给用户自己的结果页。
- 结果页底部自然露出 1-3 条“同主题心愿”，不是跳广场。
- 用户可以直接关闭，不损失任何东西。
- 送好运动作必须低于 3 秒：点一下好运符号即可，不要求评论、不要求选择复杂表情。
- 送完后立即回到自己的卡片，不进入社交流沉没。

验证路径：

[假设: 情绪仪式完成后，用户仍有短暂的“愿意把好运扩散出去”的窗口。]  
验证方式是 A/B 测试三种路径：仪式后直接结束、仪式后露出 1 条同主题心愿、仪式前露出心愿。比较送出率、关闭率、次日负反馈、用户对“被打扰”的评分。

### U3【接受】
“社交是主菜但允许只做仪式”如果做成“默认进入广场”，确实自相矛盾。

修订后的默认路径不是“仪式 → 广场”，而是：

**仪式 → 我的好运卡 → 卡片底部的同主题回声 → 可选进入回声池**

也就是说，主菜不是一个需要用户主动进入的广场，而是嵌在个人仪式结果里的“半匿名祝福回声”。广场降级为二级视图。

默认产品形态：

1. 用户进入某个事件主题，例如“等面试结果”。
2. 写下心愿，完成一个 30-60 秒仪式。
3. 生成“我的好运卡”。
4. 卡片下方露出 1-3 个同主题、异步的匿名心愿。
5. 用户可点一下“送好运”，也可直接离开。
6. 若用户继续滑动，才进入更完整的回声池。

这样社交仍是产品不可替代点，但不是压迫式默认跳转。

### B1【接受】
这是最高风险点，我接受。同步广场在低频产品里很难成立，尤其“等面试”这种时间窗短的主题，实时在线密度不够。

修订机制：采用**异步时间匹配池**，不依赖同时在线。

具体规则：

1. 每个主题是一个“时间窗池”，例如“等面试结果”默认收纳过去 7 天内创建、未来 7 天内仍有效的心愿。
2. 送好运不是送给“当前在线的人”，而是送给“同主题、同阶段的历史/未来有效心愿”。
3. 被送者异步收到：下次打开时看到“有 5 个同样在等结果的人给你送了好运”。
4. 心愿过期后进入“回声档案”，仍可被展示为已完成的匿名片段，但不再接收新祝福。
5. 单一主题池优先，不早期拆太细。比如先只做“考试/面试/结果等待”之一，而不是同时开很多人生场景。
6. 不用机器人。空池时显示真实空状态，并回到自我仪式兜底，例如“现在这个池子很安静，你可以先把好运留给自己”。

这打破“必须同一时刻在场”的约束。广场成立的前提从“实时密度”改为“时间窗密度”。

### B2【接受】
原先“积福值 → 福气卡”的链条没有切断，只是弱化了压力。修订为：

- 积福值不再驱动给予。
- 福气卡不靠稀缺、兑换、收藏完整度吸引用户。
- 给予最终靠情感动机，而不是奖励动机。

福气卡的吸引力来自三点：

1. **自我确认**：把用户的心愿、仪式动作、关键词生成成一张可保存的好运卡。
2. **他人回声**：卡片可能带上真实祝福回声，例如“7 个同样在等结果的人把好运给了你”。
3. **结果闭环**：用户可在几天后回来标记“中了/没中/还在等”，系统把这次等待收束成一张回顾卡。

送好运靠什么？

- 靠“我也在经历这个，所以顺手给你一点好运”的同境共情。
- 靠极低成本动作。
- 靠异步收到他人祝福后的轻互惠。
- 不靠攒分、不靠换卡、不靠排名。

所以“双货币”如果指可见经济系统，我修订为：不成立，应该砍掉兑换链。保留的是“双反馈”：自我好运卡 + 社交回声痕迹。

### B3【接受】
“大多数不进广场”必须有预警线。

修订指标：

1. 仪式完成率：核心底盘，低于 55% 说明自我仪式不成立。
2. 仪式后送好运率：目标 20%-35%。低于 10% 说明社交只能做彩蛋。
3. 收到祝福后的回访率：目标高于未收到祝福用户 15% 以上。
4. 心愿有效收到真人祝福比例：目标 80% 以上，低于 50% 说明池子密度不足。
5. 用户主观压迫感：若超过 15% 用户反馈“像任务/被要求互动”，必须继续降社交强度。

种子用户不能被安排“任务式送好运”，否则数据失真。可以做的是主题冷启动：邀请真实处在该事件窗口的人进入同一主题池，但不要求他们完成固定互动 KPI。

## Revised Proposal（修订立场）

### [REVISED] 1. 双货币能否驱动给予 / 该不该砍
可见双货币经济应该砍。最终形态不是“积福值兑换福气卡”，而是：

- **好运卡**：自我仪式的结果物，人人完成仪式即可获得。
- **福气回声**：真实他人祝福留下的轻痕迹，只增强卡片内容，不作为资源。
- **积福值**：不再作为用户侧货币，只保留为后台节奏信号或直接改名为“给予痕迹”。

给予最终靠情感共鸣、低成本动作、异步互惠，不靠奖励。

### [REVISED] 2. 零焦虑与留存是否矛盾
不矛盾，但不能追求日活。留存来自事件周期内的自然回访：

- 写心愿当天。
- 等待中收到祝福时。
- 结果出来后回填结果。
- 下次遇到类似事件时再来。

产品要接受低频，但要提高“一个事件周期内的完成度”。

### [NEW] 3. 社交主菜还是彩蛋
社交仍是主菜，但主菜形态从“广场”改为“嵌入式回声”。

默认路径：

**选择主题 → 写心愿 → 完成仪式 → 生成好运卡 → 露出 1-3 条同主题异步心愿 → 可选送好运 → 可选进入回声池**

用户不需要主动跳出才能保持低压，也不会被强制推进广场。社交价值被放在个人仪式结果页里，以“回声”而不是“社区”的方式出现。

### [NEW] 广场时间匹配机制
使用异步时间窗池：

- 主题池按事件阶段聚合。
- 心愿在有效期内可异步接收祝福。
- 祝福者可以给过去 N 天内的真实心愿送好运。
- 被祝福者下次打开时收到汇总回声。
- 空池不伪造真人，直接回到自我仪式兜底。

## Evidence and Rationale（证据与理由）

[假设: 用户在相似处境中更容易产生轻量共情。]  
验证路径：比较“同主题心愿”与“随机心愿”的送好运率、停留时长、关闭率。

[假设: 可见积分会诱发目标化行为。]  
验证路径：测试“显示数字积分”与“只显示一句痕迹反馈”的压力评分、重复送出率、负反馈率。

[假设: 异步祝福足以产生被陪伴感，不要求实时互动。]  
验证路径：比较“实时在线祝福提示”和“过去 7 天同主题祝福汇总”在安慰感评分上的差异。

[假设: 零焦虑产品的关键不是没有回访，而是不制造亏欠式回访。]  
验证路径：观察事件周期内自然回访，而不是日活；同时收集“是否觉得被催促回来”的主观反馈。

## Trade-offs Acknowledged（权衡）

1. 砍掉兑换链后，短期行为刺激会变弱。
2. 不做排行榜、等级、稀缺卡，会牺牲增长型游戏化效率。
3. 异步池比实时广场更稳，但现场感更弱。
4. 社交嵌入个人结果页后，社区感会变轻，不适合做高互动社区。
5. 单一主题池有利于密度，但早期场景扩展会慢。

## Open Questions（开放问题）

1. 单一主题池先选“考试等待”“面试等待”还是“抽签/开奖/结果等待”。
2. 心愿有效期应是 3 天、7 天还是 14 天。
3. 福气回声是否允许用户写短句，还是只允许一键符号祝福。
4. 结果回填是否应该匿名进入回声档案，成为后来用户的安慰材料。
