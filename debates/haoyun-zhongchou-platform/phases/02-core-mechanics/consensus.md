# 阶段 2 共识 · 核心机制（双货币 & 零焦虑）

> 2 轮辩论。第 1 轮 6 条必须回应已在第 2 轮全部解决；第 2 轮新增 4 条张力（含根本性的 NB-2），带入后续。

## 已达成共识

1. **可见双货币经济应砍掉**（解决 Phase 1 张力 T1）。最终改为"**双反馈**"：
   - **好运卡**：自我仪式的结果物，人人完成仪式即得（不靠攒、不靠换）。
   - **福气回声**：他人真实祝福留下的轻痕迹，只增强卡片内容，**不作为资源/货币**。
   - **积福值**：退为后台节奏/风控信号（或改名"给予痕迹"），**用户侧不可见、不驱动行为**。

2. **给予改为情感驱动**，不靠奖励：同境共情（"我也在经历，所以顺手给你一点好运"）+ 极低成本动作（<3 秒点一下）+ 异步轻互惠。福气卡吸引力来自自我确认 + 他人回声 + 结果闭环（几天后回填"中了/没中"收束成回顾卡）。

3. **零焦虑与留存不矛盾，但放弃日活执念**。留存 = 事件周期内的自然回访（写心愿当天 / 收到祝福时 / 结果回填 / 下次类似事件复用），不是每日签到。追求"一个事件周期内的高完成度"。

4. **社交是主菜，但形态从"广场"改为"嵌入式回声"**。默认路径：
   `选主题 → 写心愿 → 完成 30–60 秒仪式 → 生成"我的好运卡" → 卡片底部露 1–3 条同主题异步心愿 → 可选送好运(<3秒) → 可选进入回声池`。
   广场降为二级视图；用户无需主动跳出即保持低压，也不被强制推进社区。

5. **广场用"异步时间窗池"打破"必须同时在场"**：主题=时间窗池（如"等面试"收纳过去 7 天创建、未来 7 天有效的心愿）；送好运给同主题历史/未来有效心愿；被送者异步收到汇总回声；过期进"回声档案"。**空池不伪造真人**，显示真实空状态并回到自我仪式兜底（守住 C1.4）。

6. **MVP 预警指标（带阈值）**：仪式完成率<55% 自我仪式不成立；仪式后送好运率目标 20–35%，<10% 社交只能做彩蛋；收到祝福回访率应高于未收到 15%+；心愿收真人祝福比例目标 80%+，<50% 池密度不足；主观压迫感>15% 须降社交强度。种子用户不安排任务式互动。

## ⚠️ 对 spec 的重大偏离（需用户最终确认）
- 本阶段实质上**重写了 spec 的"双货币骨架 + 福气卡兑换 + 广场"三块**：双货币→双反馈、福气卡从"积福值兑换+稀有度图鉴"→"仪式结果物+情感锚定"、广场从"实时互祝"→"异步时间窗池+嵌入式回声"。Phase 1 张力 T1 由辩论给出结论=砍可见双货币，**待用户拍板**。

## 开放张力（带入后续阶段）
- **NB-2（根本性）情感驱动的持续性 + 基础密度**：共情窗口仅几天，窗口外用户共情衰减但产品需要他们继续送好运；冷启动期情感与奖励都缺失。事件窗口结束后靠什么驱动给予、事件间隔期池子如何不空 → **Phase 4（增长/留存）+ Phase 5（是否成立）核心议题**。
- **NUX-1 异步祝福的"被陪伴感"真实性**：聚合通知感 vs 真实人际连接。需在情感设计上想办法让接收者感到"真有人那一刻想到我" → Phase 3。
- **NUX-2 送者落地感缺失**：时态错位 + 无闭环反馈→重复后麻木 → Phase 3。
- **NB-1 长尾主题空池断点**：核心情绪价值的单点失败；主题颗粒度"聚合 vs 精准"取舍 → Phase 4。
- **NB-3 结果回填率低切断异步互惠闭环**：回填提醒如何不制造焦虑 → Phase 4。
- **存档-U1** 嵌入回声 vs 仪式纯粹感，A/B 关闭率时间分布留意。
